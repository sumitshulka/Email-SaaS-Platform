---
name: pg-mem with Drizzle
description: Compatibility details for isolated Drizzle tests using pg-mem's node-postgres adapter.
---

When using pg-mem 3.x with Drizzle's node-postgres driver, intercept pool and connected-client queries to remove the unsupported `types` and `rowMode` options. For `rowMode: "array"` queries, convert pg-mem's object rows to arrays in their existing property order, which follows the selected-column order expected by Drizzle. pg-mem also does not support `FOR UPDATE SKIP LOCKED`; test adapters may reduce it to `FOR UPDATE` when lock skipping itself is not under test. For UTC monthly-grouping route tests, register narrow test-only shims for `AT TIME ZONE`, `date_trunc`, and `to_char`; do not weaken valid PostgreSQL production expressions just to fit pg-mem's partial SQL support.

For one-time database claims, pg-mem 3.x reports the existing row from `INSERT ... ON CONFLICT DO NOTHING RETURNING` as if it were inserted. Prefer a conditional `UPDATE ... WHERE consumed_at IS NULL RETURNING` for consume-once state, or add a test-adapter shim if insertion itself is required.

Keep reduced test DDL aligned with production column nullability as well as names and types. In particular, `user_subscriptions.payment_id` must remain nullable so gift and free subscription terms can be represented without a payment.

**Why:** pg-mem's adapter rejects both options and the `SKIP LOCKED` clause, and its optional wire-protocol server has failed on parameterized comparisons with a missing execution context. It also omits common PostgreSQL date/time functions and timezone operators, and its `ILIKE` handling does not mirror PostgreSQL backslash escaping for `%` and `_`; explicit `ESCAPE` and `strpos` expressions are unsupported by its parser. The direct in-memory adapter avoids a real or production database while preserving route-level database behavior. Its conflict-returning behavior can also invalidate otherwise-correct single-use tests. Reduced DDL that tightens nullable columns can reject valid states that production accepts.

**How to apply:** Keep test DB injection guarded by `NODE_ENV === "test"`, install it before importing routes, and run the test suite against that isolated database rather than connecting to the configured application database. Implement only the function units/formats used by the query fixtures, with UTC semantics matching the seeded timestamps. Reduced test table definitions must include columns with Drizzle `$onUpdate` callbacks and retain production nullability; Drizzle may write those columns during an update to a different field. Strip `SKIP LOCKED` only in test adapters; preserve production locking semantics. If literal wildcard search becomes a requirement, verify its SQL semantics against PostgreSQL rather than treating pg-mem's `ILIKE` escaping behavior as authoritative.
